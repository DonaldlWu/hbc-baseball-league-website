# 從最近七天貼文更新賽程

沒有提供公告時，自 HBCWebsite 根目錄執行一次共用入口：

```sh
node .codex/skills/hbc-update-game/scripts/fetch-weekly-reports.mjs --kind schedule
```

先閱讀[共用抓取規則](../../hbc-update-game/references/weekly-fetch.md)的抓取、日期、作者 ID、冷卻、操作預算與輸出規則；後面的戰報比分/試算表更新步驟不適用賽程。

同時更新戰報和賽程用 `--kind all` 抓一次，分別讀取 reportPosts 和 schedulePosts。已取得同社團、相同七日範圍的原始 JSON 時，用 `--input PATH --as-of YYYY-MM-DD --kind schedule` 重用，不再連 Facebook。JSON 必須是 rawReport 指向的原始結果，不能是只剩戰報的篩選檔。

預設僅抓取最近七個台北日曆日（含當天）發布的公告、最多兩個候選、逐篇等待五秒。不保證完整，達上限或零結果不自動重試。貼文可能是月賽程，應解析其中所有有明確日期的場次，包括未來日期；不以發文日期補缺少的比賽日期。作者只使用既定帳號 ID，不加入人名設定。

## 分析與本機更新

1. 讀 selectedPath 的 schedulePosts、unresolved 與 scan。含未展開、空白、身分/日期不確定的候選列待確認。混合公告只將 VS 賽程行交給本 skill，比分結果行交給更新戰報，不重複新建場次。
2. 依同一篇公告的日期/場地標題切分場次；不可跨貼文繼承標題。需要有效日期、雙方球隊、場地及完整時間。隊名以專案 season game 與 teams.json 為準；錯字/漏字沒有獨立證據不能自動配對，也不能新建未知球隊。
3. 完整編號（例如 No.2026098）保持原編號及明確賽季；季後賽保持完整 G 編號並使用 postseason 檔。短編號（No.98）先在相關 indexed 賽季查既有同場次和隊伍，避免將舊賽季補賽誤建到新賽季。新場次才用比賽日期查 regular-season index；有 file 指向 postseason 的索引不參與一般賽季選擇。月份重疊、同編號多賽季或隊伍證據不足均列待確認，不能直接用最新年份。
4. 新場次完整且唯一才新增 scheduled，比分 null、sheetId 空字串。VS 前客隊/先攻、後主隊/後攻；以實際時間判斷時段，未知時間格式列待確認。
5. 既有同安排判定無變更，即使公告重發或 game 已 finished，也不得重設結果或改為 scheduled。比較補賽時將省略的場地/時間按原場次補齊後比較；相同日期及安排不重複 append。
6. 已有 rain 且確定是新的補賽安排，才 append rescheduledDates，保留原 date、場次、狀態、結果及歷史。較早公告不得覆蓋新安排；同日期不同時段、場地或隊伍的差異列待確認。未出現在公告的既有場次不自動取消或刪除。
7. 先產生新增／補賽／無變更／待確認差異，再重讀檔案避免覆蓋人工作業，僅寫入可驗證的本機資料。不重算戰績；有實質變更才改 lastUpdated。只有新增賽程權限不代表可以更新比分或籤表結果。
8. 驗證變更 JSON 與專案相關檢查。回報來源範圍、處理數、實際賽程日期、去重結果、待確認項及掃描停止原因。沒有可用公告時明確回報本次未取得，不宣稱本週沒有賽程。不自動 commit、push、部署或建立排程；有當次明確授權則依其範圍執行。

## 範例驗收

- 11/9 發布、12/5 比賽：抓取符合本週範圍，場次日期仍是 12/5。
- 相同 No.98 公告重複執行：不重複新增，不改 lastUpdated。
- 舊賽季雨延場次安排於新賽季月份：保留舊 gameNumber，只補入補賽歷史。
- 既有補賽只存 date，公告新增相同預設場地/時間：視為同一安排，不重複 append。
- 隊名拼錯、缺隊名或索引範圍重疊：列待確認，保留專案名稱。

這些匹配/寫入由 skill 的 agent 執行，helper 只負責有界抓取與候選分類，不是確定性賽程匯入器。helper 的本機測試涵蓋短編號、未來日期、混合公告一次抓取及 raw JSON 重用。
